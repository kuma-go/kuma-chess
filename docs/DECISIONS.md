# 결정 기록

## 2026-09-02: 초대 코드 기반 비랭크 온라인 대전

- 온라인 첫 단계는 공개 방 목록이나 자동 매치메이킹 없이, 추측하기 어려운 6자리 초대 코드를 직접 공유하는 지인 1:1 체스로 제한한다.
- 방 생성, 초대 코드 입력, 상대 대기 UI는 게임 장면을 따로 만들지 않고 웹 메인 위의 기존 양피지 팝업과 버튼 리소스를 재사용한다. 두 플레이어가 연결된 뒤에만 콘텐츠 iframe의 온라인 체스 장면을 연다.
- 방장은 백, 참가자는 흑으로 시작한다. 각 기기는 자기 진영만 조작하고 흑 화면은 보드를 180도 반전해 자기 기물이 아래에 오도록 표시한다.
- Firestore 방 목록 조회는 금지하고 정확한 코드 조회만 허용한다. 수 갱신은 참가자 UID, 현재 차례 UID, 단조 증가하는 `revision`을 모두 확인해 중복 수와 오래된 위치 덮어쓰기를 막는다.
- 브라우저나 게임 오버레이를 잠시 닫아도 즉시 기권시키지 않는다. 로컬에 활성 방 코드와 진영을 저장해 같은 Firebase 익명 UID로 온라인 메뉴에 다시 들어오면 대기방 또는 진행 중 대국을 복구한다. 명시적으로 나가기를 확인한 경우에만 기권 처리한다.
- 정적 웹 클라이언트와 Firestore 규칙만으로 체스 수의 합법성을 신뢰할 수 있게 검증할 수 없으므로 현재 온라인 대전은 비랭크이며 코인, 메달, 공식 순위에 반영하지 않는다. 해당 보상은 서버 함수에서 수를 재생·검증하는 단계 이후에 활성화한다.
- 결과 화면의 신규 메달 연출은 코인·기물 알림보다 먼저 재생하고, 사용자가 메달을 확인하기 전에는 재경기와 메인 이동을 잠가 빠른 화면 전환으로 연출이 유실되지 않게 한다.
- 온라인 대국에서도 일반 체스의 체크·체크메이트 라인과 잡은 기물 표시를 유지한다. 참가자 닉네임 옆에는 방 문서에 저장한 공개 초상·테두리 ID를 표시하되, 보유 여부나 코인 정보는 공유하지 않는다.
- 초대 코드 입력과 대기처럼 작은 3패치 팝업은 메인 화면 위의 딤드·블러 상태로 표시한다. 중앙 조각은 상단과 하단 리소스 사이에서만 늘려 투명 영역에 겹치지 않게 한다.
- 공성전 AI 승리는 다른 AI 대전과 동일하게 난이도별 코인 보상을 지급하며, 시작 전 난이도 카드에도 해당 보상을 표시한다.

## 2026-09-01: 프로필 꾸미기와 리더보드 사전 화면

- 프로필은 닉네임, 199종 초상, 15종 테두리를 조합한다. `기본` 이름의 초상 8종과 테두리 4종은 자동 보유하고, 나머지는 코인으로 해금한다.
- 초상은 60코인, A 테두리는 150코인, B 테두리는 300코인, C 테두리는 500코인으로 시작한다. 가격은 서버 지갑 이전의 로컬 밸런스 값이며 온라인 경쟁 이점은 제공하지 않는다.
- 선택한 초상과 테두리는 프로필 표현 정보로 Firebase 동기화할 수 있지만, 코인과 구매 소유권은 클라이언트가 신뢰할 수 없는 값이므로 리더보드나 온라인 대전의 권한 근거로 사용하지 않는다.
- 199개 초상을 초기 부팅에서 모두 디코딩하지 않는다. 페이지 번호 없는 연속 스크롤 목록에서 현재 보이는 행과 실제 선택 항목만 지연 로드하고 서비스 워커 런타임 캐시에 저장한다. 보유 항목은 목록 위쪽에 안정 정렬한다.
- 미보유 초상과 테두리도 선택 즉시 미리보기에 반영하되 코인은 차감하지 않는다. 선택 즉시 총액과 구매 후 잔액 또는 부족액을 표시하고, `적용` 뒤 별도 구매 확인 팝업에서 동의한 경우에만 전체 항목을 한 번에 해금한다. 잔액 부족 시 적용 버튼을 비활성화하며 일부 항목만 구매되는 상태를 허용하지 않는다.
- 표시용 닉네임은 Firebase `nicknameClaims` 문서를 트랜잭션으로 예약해 중복을 허용하지 않는다. 닉네임 변경 팝업의 `저장`은 서버 예약에 성공한 경우에만 초상·테두리 편집과 독립적으로 즉시 반영되어 이후 프로필 편집을 취소해도 유지한다.
- 화면 명칭은 `리더보드` 대신 `체스 순위`를 사용한다. 서버 검증 점수 정책이 확정되기 전까지 임의의 경쟁자나 가짜 점수를 만들지 않고, 현재 기기의 승리 기록은 `로컬 기록·순위 미등록`으로만 보여준다.
- 읽기 전용 온라인 순위는 `leaderboards/weekly-current/entries`와 `leaderboards/all-time/entries`의 서버 작성 문서를 사용한다. 주간 기록이 없으면 전체 최고 기록자와 마지막 갱신 상대 시간을 표시하고, 클라이언트 쓰기는 계속 금지한다.
- 공식 시즌 순위, 주간 순위, 친구 순위, 보상, 명예의 전당은 등록형 계정, 서버 검증 게임 이벤트, 서버 지갑 이후 활성화한다.
- 메달 `왕국의 명예`에는 최상위 AI 승리뿐 아니라 장기 수집과 꾸준함을 대표하는 코인 마스터, 보물 수집가, 성실한 기사, 왕국의 일과, 백일의 수련, 미니게임 마니아를 배치한다. 개별 경기 기술과 미니게임별 도전은 `위대한 도전`에 유지한다.

## 2026-08-02: 첫 WORLD 미니게임은 왕국 힘겨루기

- 허브 화면보다 먼저 기존 체스보드와 기물 리소스를 재사용한 미니게임 감각을 검증한다.
- 각 진영은 폰 5개와 나이트·비숍·룩·퀸·킹 1개씩, 총 10개 기물로 시작한다.
- 기물마다 반지름, 질량, 힘 전달, 최고 속도를 다르게 두며 킹은 무겁지만 느리게 둔다.
- 승패 조건은 상대 킹을 판 밖으로 밀어내는 것으로 제한한다. AI 승리는 선택한 난이도에 따라 일반 AI 대전과 같은 5·15·35코인을 경기 세션당 한 번 지급하고, 마주보기 대전에는 코인을 지급하지 않는다.
- 왕국 힘겨루기도 기존 체스처럼 기물 선택 흐름을 거쳐 AI 대전과 마주보기 모드를 모두 지원한다.
- 승패가 결정되면 미니게임 전용 팝업 대신 일반 체스와 같은 결과 화면과 승리 연출을 사용한다.
- 드래그 100% 샷은 길이 열려 있으면 반대편 판 끝을 넘어갈 수 있을 정도로 강하게 두어 힘 조절 자체를 플레이의 핵심으로 만든다.
- AI 난이도는 단순 파워 차이만이 아니라 조준 오차, 목표 선택, 기물 선택 로직 차이로 구분한다.
- 일반 체스 AI 난이도 선택은 기존 세 난이도를 한 줄 카드로 유지하고, 성격이 다른 최상위 `도전` 난이도는 그 아래 전폭 버튼으로 분리한다. 팝업 원본 리소스 비율을 유지해 늘어짐 없이 표시한다.
- 힘겨루기 AI의 보통·어려움은 사거리만큼 파워를 보정하고, 아군 기물에 막히지 않는 발사 경로와 킹·가장자리 취약 기물을 우선 평가한다.
- 어려움 AI는 자기 킹의 받침이 판 끝에 가까워지면 공격보다 생존을 우선하고, 막힘이 적은 방향으로 킹을 안쪽에 재배치한다. 보통 AI는 더 좁은 위험 구간에서만 같은 방어를 수행한다.
- 왕은 다른 기물보다 훨씬 무겁고 둔하게 두어 초반 강샷 한 번으로 게임이 바로 끝나지 않게 하며, 충돌 시 가벼운 기물을 튕겨내는 중심 역할을 한다.
- 마주보기 모드에서는 처음부터 한쪽만 뒤집지 않고, 일반 체스처럼 현재 턴이 흑일 때 전체 기물을 위쪽 플레이어 기준으로 상하반전한다.
- 충돌 원은 기물 중심이 아니라 하단 받침 쪽에 두고, 아트보다 작게 보여 기물의 접지면과 충돌 예측을 맞춘다.

## 2026-08-30: Firebase 클라우드 기반 1단계

- Firebase 웹 설정은 공개 식별자이며 저장소에 포함할 수 있지만, Admin SDK 서비스 계정과 개인 키는 클라이언트·저장소에 넣지 않는다.
- 익명 인증 UID 아래에 프로필 설정과 검증 전 진행 요약만 저장한다. 로컬 저장은 계속 게임 실행의 기준이며 Firebase 장애가 플레이를 막지 않는다.
- 코인, 보상 청구, 보유 기물, 리더보드와 공식 승리는 클라이언트가 쓸 수 없다. 해당 경로는 Firestore 규칙으로 차단하고, 추후 서버 함수가 이벤트를 검증해 원장을 갱신한다.
- 익명 계정은 브라우저를 지우면 복구할 수 없으므로 기기 간 동기화 공개 전 Google 등 등록형 계정 연결과 앱 내 삭제 기능을 추가한다.
- Analytics는 동의·개인정보 결정을 별도로 마친 뒤 도입하며 이번 Firebase 초기화에는 포함하지 않는다.
