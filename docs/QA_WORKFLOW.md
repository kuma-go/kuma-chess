# KUMA CHESS QA 워크플로

변경 위험도에 맞는 최소 검증을 선택한다. 작은 디자인 수정 뒤 전체 저장소 QA나 서브에이전트 검수를 반복하지 않는다.

## 빠른 QA

대상: 간격, 크기, 좌표, 문구, 단일 이미지 교체처럼 상태와 보상 로직을 바꾸지 않는 수정.

```bash
npm run qa:quick
npm run qa:quick -- profile
```

- 모든 `src/**/*.js` 문법과 `git diff --check`를 검사한다.
- 대상을 지정하면 관련 검증기 하나만 추가한다.
- 바뀐 화면만 직접 열어 대표 뷰포트 하나에서 확인한다. 반응형 영향이 있으면 데스크톱과 모바일을 모두 본다.
- 서브에이전트와 전체 화면 순회는 사용하지 않는다.

## 기능 QA

대상: 클릭 흐름, 팝업 상태, 구매·적용, 저장, 보상, 프로필 동기화처럼 동작이 달라지는 수정.

```bash
npm run qa:feature -- profile
npm run qa:feature -- ai
```

- 문법·diff 검사에 대상 기능 검증기를 더한다.
- 변경 기능의 성공·취소·부족/오류 상태를 확인한다.
- 영향을 받는 화면만 데스크톱과 모바일에서 확인한다.
- 구현이 여러 시스템을 가로지르거나 판단이 모호할 때만 별도 검토 에이전트를 사용한다.

## 전체 QA

대상: 배포 직전, 공개 푸시 전, 저장 스키마·코인·보상·보안·공통 UI 도우미 변경, 큰 기능 병합, 사용자의 명시적 전체 검수 요청.

```bash
npm run qa:full
npm run qa:release
```

- 전체 검증기와 보안 검사를 실행한다.
- `qa:release`는 Git 이력의 민감정보 검사도 포함한다.
- 핵심 진입 화면과 변경 기능을 데스크톱·모바일에서 확인한다.
- 디자인·기획·개발·보안의 독립 검토가 필요하고 사용량 여유가 있을 때만 에이전트를 추가한다.

## 대상 이름

`ai`, `core`, `crown`, `daily`, `firebase`, `main`, `medals`, `online`, `pieces`, `profile`, `puzzle`, `ranking`, `road`, `siege`, `tug`를 사용할 수 있다.

실패하지 않은 명령의 상세 출력은 보고하지 않는다. 실패한 검사와 실제로 확인한 화면만 요약해 토큰과 검토 시간을 줄인다.
